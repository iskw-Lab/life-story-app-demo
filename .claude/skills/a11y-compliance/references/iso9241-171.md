# ISO 9241-171:2025 checklist (software accessibility)

ISO 9241-171:2025 — Ergonomics of human-system interaction — Part 171: Guidance on software accessibility (https://www.iso.org/standard/86308.html).

The standard is paywalled. This checklist follows its published structure: general guidelines, inputs, outputs, documentation and support. Items are phrased as checks for this app. When a finding depends on exact clause wording or numbering, record it as 「要原文確認」 and do not cite a clause number from memory.

## A. General guidelines
| ID | Check |
|---|---|
| G-1 Names and labels | Every UI element has a name that is shown and exposed to assistive technology. Names are unique within a screen and consistent across screens |
| G-2 User preferences | Users can set and keep their presentation preferences: text size, furigana, read-aloud, reduced motion, theme. Settings persist per user/device. The app follows OS settings (`prefers-reduced-motion`, `prefers-color-scheme`, `prefers-contrast`) |
| G-3 Accessibility adjustments | Accessibility features are easy to find and to turn on/off. Turning one on does not break another (e.g. large text plus the read-aloud layout) |
| G-4 General control and operation | Users can stop, pause, undo and cancel. No forced time limits. Errors are prevented or recoverable. Users are warned before irreversible actions. Users can move away from any state |
| G-5 Compatibility with assistive technology | Standard HTML controls are preferred. Custom widgets expose name/role/state/value. Focus and selection are programmatically determinable. Changes are announced |
| G-6 Closing/escaping | Every modal, drawer or overlay closes by keyboard (Esc) and has a visible close control |

## B. Inputs
| ID | Check |
|---|---|
| I-1 Alternative input styles | Each task can be done by keyboard alone, pointer alone, or touch alone. Speech input works via visible labels |
| I-2 Keyboard focus | Focus is always visible and logically ordered. It is not lost after re-render; restore focus to the equivalent element after `innerHTML` updates |
| I-3 Keyboard input | Standard keys (Tab, Shift+Tab, Enter, Space, Esc, arrow keys within composite widgets). No required chorded shortcuts. Any shortcut can be remapped or disabled |
| I-4 Pointing devices | Targets are large enough (≥ 24 px; ≥ 44 px on tablet/本人向け). No double-click or hover-only functions. Drag has an alternative. Actions fire on release |
| I-5 Timing of input | No time-dependent input. Long-press and repeat delays are not required |

## C. Outputs
| ID | Check |
|---|---|
| O-1 Visual output | Information is not conveyed only by colour, position or shape. Contrast is adequate in both themes. There is no flashing |
| O-2 Text and fonts | Text uses system fonts and scales to 200%. Ruby/furigana is selectable. Line length and spacing are readable |
| O-3 Colour | Layer and status palettes are distinguishable for colour-vision deficiencies (validated) and are paired with labels |
| O-4 Window appearance and behaviour | Layout reflows. Sticky elements don't obscure content. No unexpected pop-ups; dialogs open only on user request |
| O-5 Audio output | Read-aloud can be paused/stopped and its volume set by the system. Audio is never the only channel |

## D. Online documentation, help and support
| ID | Check |
|---|---|
| D-1 | Help (legend 「読み方」, 「てつだって」) is available in an accessible format, in the same place on each screen, and written in plain language |
| D-2 | Documentation describes the accessibility features and how to change preferences |
| D-3 | There is a way to contact a human: the supporter or facilitator is named on 本人向け screens |
